Delivery timeline

built incrementally, tests after each step
✓

Build & audit · reproduced, not assumed

End-to-end middleware (retrieval → generate → claims → verify → safety → bounded repair → strict release), then a repository audit that re-ran tests and metrics and surfaced the consumed-test-set and leakage risks.

P0

Data integrity & honest held-out evaluation

Frozen final_test_v1 (provisions disjoint from dev), SHA-256 manifests, leakage checker, and a frozen-artifact hash stamped into every run. The consumed test split is labelled as such.

P1

Retrieval metrics & consumption guard

Recall@k / MRR with a config comparison, plus a freeze-ledger that auto-flags the frozen set if code changes between runs.

P2

Legal provenance & multi-format ingestion

Document type, court, citation, effective/amendment dates and licence in the schema; PDF + TXT + DOCX; scanned-PDF detection that fails clearly instead of indexing empty text.

P3

Engineering hardening

Git + pinned dependencies, a tamper-evident audit hash chain, privacy-conscious retention, and an admin gate on sensitive surfaces.

API

REST admin gate

The same token gate on /history, /report, /documents and the /admin/* maintenance endpoints, with tests.

Verification pipeline

question → safety screen → retrieve evidence
  → draft (held back) → atomic claims
  → 9 independent signals: NLI · numeric ·
    statute · currency · attribution · scope…
  → bounded repair → strict release
  → released answer or explainable withholding

Known limitations

stated, not papered over
  • Labels are single-reviewer and model-authored; a publishable benchmark needs independent human annotation and a second reviewer.
  • The benchmark is small (33 frozen items), so intervals are wide and the perfect frozen scores will drop on a larger, independently labelled set.
  • Corpus is three statutes (BNS 2023, IT Act 2000, Constitution); the schema supports judgments and other laws, but no large case-law corpus is ingested.
  • The admin gate is a single static token, appropriate for one node — not multi-user authentication.

Using it to ask a legal question

the interactive workflow, verified live

The Streamlit app's Legal Query Workspace takes a question, runs it through the real pipeline and configured LLM (no canned answers), shows each stage as it completes, and reveals the draft only if the release policy passes — otherwise an explainable withholding, never the hidden draft. Verified end-to-end against a local Ollama model.

ollama serve  ·  ollama pull qwen2.5:3b
python -m scripts.init_kb --no-download  # index the corpus
python -m streamlit run app.py  # open Legal Query Workspace

Example answered live: “punishment for extortion under the BNS” → released, Section 308, cited to p.81, ~40 s on CPU. Out-of-corpus questions are withheld as insufficient evidence, not answered from model memory.
